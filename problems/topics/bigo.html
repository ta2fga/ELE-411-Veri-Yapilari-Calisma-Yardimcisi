Big-O, girdi boyutu N büyürken algoritmanın çalışma süresinin (en kötü durumda) nasıl büyüdüğünü gösterir. Sabitler ve küçük terimler atılır: 3N² + 5N + 2 → O(N²).

Büyüme sırası

O(1) < O(logN) < O(N) < O(NlogN) < O(N²) < O(N²logN) < O(N³) < O(N⁴) < O(2ᴺ)

Döngü kalıpları

KalıpKarmaşıklık
for (i = 0; i < N; i++)O(N)
for (i = 1; i < N; i *= 2) veya i /= 2O(logN)
İç içe iki döngü, ikisi de N’ye bağlı (j > i gibi üçgen döngü dahil: N(N+1)/2)O(N²)
Dış döngü N, iç döngü j *= 2O(NlogN)
Her adımda 2 recursive çağrı, boyut 1 azalıyor (Hanoi)O(2ᴺ)

Binary search en kötü durumda ⌊log₂N⌋ + 1 karşılaştırma yapar (her adımda aralık yarıya iner) → O(logN).

Sınav tuzakları

  • for (i = 0; i < n; i = i * 2): i = 0 ile başladığı için i hep 0 kalır → sonsuz döngü! Amaçlanan (i = 1 ile) O(logN).
  • Sıralı bağlı listede arama yine O(N): binary search için ortadaki elemana O(1)’de erişmek gerekir.
  • İç döngü j = N; j > i → toplam N + (N−1) + … + 1 = N(N+1)/2 → yine O(N²).
  • i /= 2 ile küçülen while döngüsü → O(logN).
